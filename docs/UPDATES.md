# Обновления

VPNforYou обновляется сам через [Sparkle](https://sparkle-project.org): раз в 6 часов (и по кнопке «Проверить обновления» в настройках или в ⌘K) он смотрит, не вышла ли новая бета-версия, и предлагает её поставить. Если VPN был включён, после перезапуска он включится снова.

## Откуда берутся версии

- После каждого изменения в `main` CI (`build-macos.yml`, задача `publish-beta`) собирает приложение, подписывает архив ключом обновлений и кладёт его в релиз [`beta`](https://github.com/aevofounder/vpnforyou/releases/tag/beta) вместе с `appcast.xml`. Решение владельца: бета-канал публикуется без ручного шага.
- Стабильные релизы (`v1.2.3`) по-прежнему выпускает только владелец: ставит тег и нажимает Publish.
- Номер сборки — время коммита, поэтому каждая следующая сборка из `main` новее предыдущей.

## Почему поддельное обновление не встанет

Каждый архив подписан закрытым ключом Ed25519. Приложение знает только открытую половину ключа (`SUPublicEDKey` в Info.plist) и отказывается ставить архив с неверной подписью, даже если кто-то подменит файл в релизе. Закрытый ключ хранится только в окружении GitHub `beta` (доступно лишь из `main`) и в Связке ключей владельца; в репозиторий и в чат он не попадает.

## Настройка (один раз, делает владелец)

1. На маке скачайте инструменты Sparkle и создайте ключ:

   ```sh
   cd ~/Downloads
   curl -LO https://github.com/sparkle-project/Sparkle/releases/download/2.9.6/Sparkle-2.9.6.tar.xz
   mkdir -p sparkle && tar -xf Sparkle-2.9.6.tar.xz -C sparkle
   ./sparkle/bin/generate_keys
   ```

   Команда сохранит закрытый ключ в Связку ключей и напечатает открытый: строку из 44 символов внутри `<string>…</string>`.

2. Открытый ключ: на GitHub **Settings → Secrets and variables → Actions → Variables → New repository variable**, имя `SPARKLE_PUBLIC_KEY`, значение — строка из шага 1 (без `<string>`).

3. Закрытый ключ кладётся не в общие секреты, а в окружение, доступное только из `main`: так его не прочитает workflow, изменённый в другой ветке.
   - **Settings → Environments → New environment**, имя `beta`.
   - В нём **Deployment branches and tags → Selected branches and tags → Add rule**: `main`.
   - Там же **Environment secrets → Add environment secret**: имя `SPARKLE_PRIVATE_KEY`. Значение возьмите так:

     ```sh
     ./sparkle/bin/generate_keys -x ~/Downloads/sparkle-private-key.txt
     open -e ~/Downloads/sparkle-private-key.txt   # скопируйте строку в секрет
     rm ~/Downloads/sparkle-private-key.txt
     ```

   Закрытый ключ никому не присылайте, в том числе Claude: кто им владеет, может выпустить «обновление» для всех, у кого стоит приложение. Копия остаётся в Связке ключей мака («Private key for signing Sparkle updates»).

4. Запустите сборку: **Actions → Build macOS → Run workflow** (ветка `main`). Через несколько минут в релизе `beta` появятся архив и `appcast.xml`.

5. Поставьте эту бету один раз вручную (архив из релиза `beta`, как в [INSTALL.md](INSTALL.md)). Сборки, скачанные раньше из Actions, ключа не знают и сами не обновятся; начиная с этой все следующие придут сами.

Если ключ потерян, новые версии придётся один раз поставить вручную после настройки нового ключа.

## Что видно при обновлении

- Окно Sparkle «Доступна новая версия» с описанием из коммита и кнопкой «Установить».
- macOS может снова спросить доступ к Связке ключей: сборка без сертификата Apple Developer каждый раз выглядит новой программой. Нажмите «Разрешить всегда».
- Если в обновлении поменялся помощник или ядро, на главном экране появится «Обновить помощника» (пароль администратора).
